# ロードマップ

## ビジョン

ユーザーが **「何も考えずにいい感じの写真が撮れる」** と感じる体験を実現する。
**「ポーズアプリ」ではなく「AI カメラマン」** として撮影ディレクションを代行する。

最終目標：**App Store でのリリース**。

---

## 開発方針

- **体験 → AI の順で作る**
- 最初は「それっぽさ」を作る（ダミー OK）
- 動くものを最優先
- 設計は後から育てる

技術ではなく **体験を作るプロジェクト**。

---

## フェーズ 0：体験プロトタイプ（最重要）

**目的：AI なしで「AI カメラマンっぽい体験」が成立するか検証**

> ここで面白くなければ、AI を入れても面白くならない。

### 実装内容

- [ ] カメラ風 UI（黒背景で OK）
- [ ] 仮シルエット表示（固定画像 or 描画）
- [ ] フィードバックテキスト表示
  - 「いい感じ！」「もう少しあご引いて」
- [ ] スコア（ダミー）
  - タイマー or ランダムで変化
- [ ] 自動シャッター演出
  - 画面フラッシュ
  - 擬似シャッター音
- [ ] 擬似保存（ログ出力で OK）

### 完了条件

- 触って「それっぽい」と感じる
- 1 分触ってもストレスがない

### 目標

**1 日で終わらせる**。

---

## フェーズ 1：MVP（非 AI）

**目的：実際のカメラと連動した体験を成立させる**

> まだ AI は使わない。UX を完成させる。

### 実装内容

- [ ] カメラプレビュー（AVFoundation）
- [ ] フレーム取得（CMSampleBuffer）
- [ ] 仮ポーズ 1 種（ハードコード）
- [ ] ダミー PoseEstimator
  - ランダム or 簡易ロジック
- [ ] スコア計算（仮）
- [ ] フィードバック表示
- [ ] 自動シャッター
  - スコア閾値 + 0.5 秒維持
- [ ] 写真保存（Photos / `PHPhotoLibrary`）

### 完了条件

カメラ起動 → フィードバック → 自動撮影 → 保存が一気通貫で動く。

---

## フェーズ 2：AI 導入

**目的：ダミーを実際の人体検出に置き換える**

### 実装内容

- [ ] MediaPipe iOS 統合（SPM 可否を要調査）
- [ ] Pose ランドマーク取得（最低：顔・肩・手）
- [ ] Face 検出（Vision Framework）
- [ ] スコアロジックを実データ対応へ変更

### 完了条件

- 実際の人の動きにスコアが追従する
- フィードバックが自然になる

### ポイント

- パフォーマンスを常に確認（FPS / 発熱）
- メインスレッドをブロックしない
- 推定は 15fps に間引く、プレビューは 30fps 以上維持

---

## フェーズ 3：コア機能強化

**目的：「AI カメラマン体験」を成立させる**

### 実装内容

- [ ] 状態テンプレート DB 導入（JSON or ローカルデータ）
  - スキーマは [design.md §2](design.md) 参照
  - 手作り 5 個から開始
- [ ] PoseMatcher 実装
  - 関節ではなく **状態スコア**（subject + composition）
- [ ] PoseRecommender
  - 距離・人数・向きベース
- [ ] ステートマシン（`SEARCH → GUIDE → CAPTURE`）
- [ ] 個別フィードバック（顎 / 肩 / 手など）

### 完了条件

- 状況に応じて自然にポーズが変わる
- ユーザーが「考えずに撮れる」

---

## フェーズ 4：UX 改善

**目的：「気持ちよさ」を最大化**

### 実装内容

- [ ] シルエット補間（スムーズ追従、0.1〜0.2 秒線形補間）
- [ ] スコアスムージング（指数移動平均）
- [ ] ポーズ切り替え制御（ヒステリシス）
- [ ] フィードバック文言バリエーション拡充
- [ ] シャッター演出（音・振動・アニメーション）
- [ ] パフォーマンス最適化（発熱・バッテリー）

### 完了条件

- 10 分使っても疲れない
- 発熱・カクつきがない
- 「気持ちいい」と感じる

---

## フェーズ 5：撮影体験拡張

**目的：「AI カメラマンらしさ」を強化（常時稼働モデルの完成）**

### 実装内容

- [ ] 撮影後の即時 LIVE 復帰（プレビュー画面なし、サムネが隅に一瞬出るだけ）
- [ ] 状態テンプレート自動切替（同じテンプレを連続選択しない、撮影直後に裏で切り替え）
- [ ] ベストショット選定（簡易、近接時刻の連続撮影から 1 枚選ぶ）
- [ ] 累積撮影カウンタ（セッション単位のフォルダ化はしない）
- [ ] 手動シャッターは残すが、UI の主役にしない

### 完了条件

- 「気づいたら良い写真が増えてる」感覚
- ユーザーが撮影フローを意識しない

---

## 重要な設計ルール（全フェーズ共通）

### ① 指示は常に 1〜2 個

- NG：「顎引いて、肩下げて、手上げて」
- OK：「顎少し引いて」

### ② ユーザーに選ばせない

- モードなし
- ポーズ選択なし

### ③ 常に褒める

- 「いい感じ」「今の好き」

### ④ 失敗を感じさせない

- 合わない → 内部で調整（近傍テンプレに切り替え）

## 将来構想（P7 以降）

## 課題・リスク（要監視）

### 技術
- MediaPipe iOS の SPM 統合方法
- リアルタイム精度と発熱のバランス
- 姿勢推定の安定性（暗所・逆光・遮蔽）
- iOS 最小サポートバージョン（現在 26.4 で過剰、要見直し）

### UX
- 状態テンプレ切り替えタイミング（頻繁すぎ／遅すぎ）
- 過剰な指示によるストレス
- 初期テンプレの質（最初の数枚で判断される）
- 公共空間で音声指示が使えないケース
- ゼロクリック開始でユーザーが普通のカメラと誤認するリスク

### プロダクト
- SNOW / SODA / Ulike との差別化を体験で示せるか
- 初回起動時のインパクト
- 状態テンプレートの "良さの定義" がブレないこと
