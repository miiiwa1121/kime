# 設計詳細（Design Doc）

このプロダクトの本質は **「良さの定義」をコードに写すこと**。
本書は、その「良さ」を表現するためのデータ構造・ロジック・UX の指針を扱う。
実装で迷った時は、まずここに戻って判断する。

---

## 1. プロダクトの再定義

このアプリは **「ポーズ提案アプリ」ではなく「AI カメラマン」**。
撮影現場でフォトグラファーが行う **構図ディレクション** をデジタル化する。

- 提案するのは「ポーズ」ではなく **「状態（姿勢 + 構図）」**
- 「腰に手を当てる」ではなく **「顔が小さく見える角度 + 体の立体感 + 手で余白調整」**
- 評価対象は被写体の関節形だけでなく、フレーム内の構図・余白も含む

---

## 2. 状態テンプレート（StateTemplate）

### 2.1 概念

完成した写真のスナップショット。被写体だけでなく構図も含めた「写真として完成した状態」を表現する。

### 2.2 スキーマ（暫定）

```jsonc
{
  "id": "tmpl_001",
  "name": "横顔・S字立ち（上半身）",
  "tags": ["solo", "upper", "standing"],

  // 被写体の状態
  "subject": {
    "face_pitch": -10,          // 顎引き角度（度）
    "face_yaw": 15,             // 左右角度
    "body_tilt": 5,             // 体の傾き
    "joints": [                 // MediaPipe ランドマークの相対座標
      { "name": "left_shoulder", "x": 0.42, "y": 0.35, "weight": 1.0 },
      { "name": "right_shoulder", "x": 0.58, "y": 0.35, "weight": 1.0 }
      // ...
    ]
  },

  // 構図
  "composition": {
    "subject_box": {            // フレーム内の被写体位置（0〜1）
      "x": 0.30, "y": 0.20, "w": 0.40, "h": 0.70
    },
    "camera_distance": "medium", // close / medium / far
    "framing": "upper_body"      // upper_body / full_body / portrait
  },

  // 将来の拡張余地（MVP では未使用）
  "background_hint": {
    "brightness": null,         // dark / normal / bright
    "clutter": null             // low / mid / high
  }
}
```

### 2.3 作成方針（段階的）

| Phase | 方法 | 数 | 時期 |
|---|---|---|---|
| **P1** | 手作り（開発者が "盛れてる" 写真を選び、MediaPipe で関節抽出 → 手で微調整） | **5 個** | MVP |
| **P2** | 写真コーパス収集（SNS 等から）+ MediaPipe 抽出 + 人手キュレーション | 数十個 | 拡張 |
| **P3** | 半自動生成（クラスタリング・embedding・潜在空間） | 連続 | 将来 |

### 2.4 P1 で作る 5 個の方向性（仮）

| # | 想定 | tags |
|---|---|---|
| 1 | 横顔・S 字立ち（上半身） | solo, upper, standing |
| 2 | 振り返り（全身） | solo, full, standing, turn |
| 3 | 座り・カフェ的（上半身） | solo, upper, sitting |
| 4 | 並び・友人 2 人（上半身） | duo, upper |
| 5 | 全身・引き構図 | solo, full, far |

具体は実装時に確定。

## 3. PoseMatcher：状態一致スコア

### 3.1 思想

「関節が一致したか」ではなく **「良い写真の状態に入ったか」** を評価する。

### 3.2 スコア構成（暫定）

```
score = w_subject · subject_score + w_composition · composition_score
```

- `subject_score`：関節差分の重み付き平均（顔・上半身に高い重み）+ 顔角度差分
- `composition_score`：被写体のフレーム内位置と `subject_box` の差分
- 重みは P1 ではハードコード。P2 でテンプレ毎にチューニング

### 3.3 スムージング

- 直近 N フレーム（例：5）の指数移動平均でスコアを安定化
- 単発の揺らぎで自動シャッターが暴発するのを防ぐ

### 3.4 閾値

- 撮影成立を優先するため厳しくしすぎない
- 初期目安：0.75 以上を 0.5 秒維持で撮影
- 実機で調整する（KPI：撮影成立までの時間、シャッター発動率）

## 4. シルエット補間（Interpolator）

### 4.1 思想

ユーザーに気づかれずテンプレートを切り替えたい。離散的なジャンプではなく、連続的に動いて見せる。

### 4.2 アルゴリズム

```
1. 現在の被写体状態 current から最近傍テンプレ nearest を選ぶ
2. 表示中のシルエット displayed を nearest に向けて補間
3. 補間時間 0.1〜0.2 秒（線形 or ease-out）
```

### 4.3 切り替えの抑制（ヒステリシス）

- 一度選んだテンプレは、明確に別の方が近くなるまで維持
- "わずかに別が近い" 程度では切り替えない（揺らぎ防止）

### 4.4 将来

- 状態空間（latent space）化、embedding ベースの連続的な変形
- MVP では実装しない

## 5. CaptureSession：セッション設計

### 5.1 思想

プロのカメラマンは 1 枚で終わらない。1 起動 = 1 セッションとして **5〜10 枚** 撮る体験にする。

### 5.2 フロー

```
起動
  ↓
人物検出
  ↓
テンプレ A 提示 → 撮影 → プレビュー 0.5s → 自動保存
  ↓
テンプレ B 提示 → 撮影 → ...
  ↓
N 枚撮影でセッション終了（or 一定時間人物未検出で終了）
```

### 5.3 セッション内のテンプレ選択

- 同じテンプレを連続選択しない
- 似すぎたテンプレも避ける（バリエーションを担保）
- P2 でレコメンドエンジンに統合

### 5.4 保存

- セッション単位でフォルダ化（例：`2026-05-07 18:30 セッション` に 7 枚）
- ベストショット選定は P3 以降

## 6. 良い顔判定（Face Quality）

### 6.1 MVP の条件

- 顔が検出されている
- 目が開いている
- 顔角度がテンプレの許容範囲内（±10 度程度）

### 6.2 後回し

- 笑顔判定（P2 以降）
- カメラ目線 vs 視線外し（テンプレに含めるか検討）
- 表情ピーク検出（連射 + 自動選別、P3）

## 7. UX 原則

### 7.1 起動体験

- 起動 → カメラビュー（UI ほぼ無し）
- 0.2 秒以内に人物検出 → シルエット出現
- 同時に視覚フィードバック開始（"いい感じ、そのまま"）
- **「今から提案します」の間を作らない**

### 7.2 オンボーディング

- 初回起動時のみ、3 秒の文言を 1 行表示
- 文言：「かざすだけで、自動でいい写真を撮ります」
- ボタンなし、タップで消える

### 7.3 フィードバックの優先順位

1. 視覚（最重要）：シルエット + 短いテキスト
2. 触覚：撮影瞬間の振動
3. 音声：デフォルト OFF、設定で ON

### 7.4 残す/隠す操作

| 残す | 隠す |
|---|---|
| ピンチズーム | モード切替 |
| 端末回転 | ポーズ選択 |
| フラッシュ設定 | 手動シャッター（基本なし） |

長押しで次候補（隠しジェスチャ）は P2 以降で検討。

### 7.5 失敗を見せない

- スコアが低いまま停滞 → ユーザーに気づかれず近傍テンプレに切り替え
- 「ダメ」「失敗」「もう一度」のような否定語を出さない
- 常に褒めベース：「いい感じ」「今の好き」「もう少しでベスト」

## 8. 技術への影響

### 8.1 MediaPipe で取るべきもの

- 顔向き（pitch / yaw）— Vision Framework と併用
- 上半身の傾き
- 手の位置
- 距離（bounding box）

### 8.2 Vision Framework

- 顔検出（`VNDetectFaceRectanglesRequest`）
- 顔角度（`VNFaceObservation.roll/yaw/pitch`）
- 目の開閉（landmarks）

### 8.3 計算負荷

- MediaPipe は 15fps に間引く
- スコア計算・補間は MediaPipe の結果が出たフレームでのみ走る
- UI 描画は 30fps を維持（補間中はクライアント側で滑らかに）

## 9. 判断に迷った時の指針

「これは実装すべきか？」と迷ったら、以下の問いに通す：

1. **ユーザーに「考える」を強いるか？** → Yes なら却下
2. **撮影体験を遅くするか？** → Yes なら却下
3. **"AI カメラマン" 的か？** → No なら却下
4. **MVP に必要か？** → 後回しできるなら後回し
